# deck-builder

Build a 5-slide + 3-appendix executive slide deck from pipeline outputs.

## Hard rules

- **Exactly 5 content slides + Appendix A + Appendix B + Appendix C** (8 slides total max).
- **Every slide title is a finding sentence**, not a topic label.
  Good: "HER2-low is the largest classifiable group but 30% of patients remain unclassifiable without curated IHC detail"
  Bad: "Q1 HER2 Distribution"
- **Every number on every slide must be sourced from a CSV** in `outputs/tables/`.
  No number is typed by hand. Read the value from the table at build time.
- **Small cells (n < 11) are displayed as "n<11"**, never as a percentage.
- State on the first or last slide: "All data are synthetic and for assessment purposes only."

## Slide structure

| Slide | Title pattern | Primary source table(s) |
|---|---|---|
| 1 | Executive summary — the answer, the verdict, top 3 caveats | q1_overall, q2_subindication_summary |
| 2 | Cohort and method — attrition flow, index date rule, HER2/HR rules | attrition, cohort |
| 3 | Q1 — HER2 distribution, 4 strata, literature comparison, unclassifiable share | q1_overall, q1_by_*, q1_unclassifiable |
| 4 | Q2 — Enhertu uptake by subindication, time to Enhertu, competitors, discordant cases | q2_subindication_summary, q2_enhertu_timing, q2_competitors, q2_discordance |
| 5 | Sensitivity, fit-for-purpose verdict, and how to productionize | sensitivity_her2_distribution, validation_report |
| App A | DQ checks table | dq_log |
| App B | Assumptions and tie-break rules | assumptions_register (from analysis_rules.yaml) |
| App C | Repo structure, pipeline diagram, 7 audit layers | ARCHITECTURE.md content |

## Implementation (python-pptx)

- Use a clean corporate template (white background, dark text, minimal decoration).
- For bar/waterfall charts, generate PNGs via `matplotlib` in `q1_distribution.py` or
  `q2_uptake.py` and embed them as images.
- Attrition flow on slide 2 is a text box with arrows, not a chart.
- Confidence intervals are shown as error bars or as "(95% CI: X–Y%)" in the table.

## Notes

- The deck is generated by `report.py` at `/build-report` time.
- Never run the deck builder on stub outputs (tables with TBD values).
- Azam reviews the deck after generation before it goes into `../_submission/`.
